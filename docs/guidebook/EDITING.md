# Редактирование гайдбука «Сектора Колосс»

Гайдбук содержит руководства для игроков, справочные статьи и каталоги из игровых данных. Текст хранится в общей рукописи; XML для игры создаётся из неё. Каталоги получают состав и характеристики при работе сервера.

## Файлы проекта

| Назначение | Путь от корня репозитория |
|---|---|
| Исходный текст статей | `docs/guidebook/GUIDEBOOK.md` |
| Импорт и проверка | `docs/guidebook/rewrite_guidebook.py` |
| Игровые XML | `Resources/ServerInfo/_LuaM/Guidebook/` |
| Новые прототипы страниц | `Resources/Prototypes/_LuaM/Guidebook/` |
| Русские названия | `Resources/Locale/ru-RU/_LuaM/guidebook/` |
| Подбор данных на сервере | `Content.Server/_LuaM/Guidebook/` |
| Передаваемые структуры | `Content.Shared/_LuaM/Guidebook/` |
| Виджеты и учебные окна | `Content.Client/_LuaM/Guidebook/` |

Часть существующих `guideEntry` находится в каталогах `_Mono`, `_NF` и других форков. Ищите страницу по **ID**, а не только по папке. Собственный новый материал размещается в `_LuaM`; изменения существующих C# и YAML отмечаются комментариями по [CONTRIBUTING.md](../../CONTRIBUTING.md).

## Изменить статью

1. Найдите нужный блок `<!-- article: … -->` в `GUIDEBOOK.md`.
2. Измените текст внутри блока. Сохраните параметры виджетов и ID внутренних ссылок, если их назначение остаётся прежним.
3. Из корня репозитория выполните:

```powershell
python docs/guidebook/rewrite_guidebook.py --apply
python docs/guidebook/rewrite_guidebook.py --check
```

`--apply` записывает XML из рукописи. Прямые изменения XML будут перезаписаны при следующем импорте. `--check` проверяет соответствие рукописи, XML-разметку, ID ссылок и иллюстраций, пути карт и структуру оглавления. Проверка не оценивает смысл текста и внешний вид окна.

Штатные автоматически создаваемые справочники рецептов химии, еды и напитков обслуживаются отдельно от рукописи.

## Добавить страницу

Добавьте блок в рукопись:

```markdown
<!-- article: Resources/ServerInfo/_LuaM/Guidebook/Engineering/Atmos/MyGuide.xml -->
# Название

Результат и необходимое оборудование.

## Запуск
1. Конкретное действие с нужным значением.
2. Следующее действие и ожидаемый результат.

[Связанное руководство](guide://ColossusAtmos)
<!-- /article -->
```

Зарегистрируйте страницу в YAML:

```yaml
- type: guideEntry
  id: ColossusMyGuide
  name: guide-entry-colossus-my-guide
  text: /ServerInfo/_LuaM/Guidebook/Engineering/Atmos/MyGuide.xml
```

Добавьте перевод `guide-entry-colossus-my-guide = Название` в русский FTL и ID `ColossusMyGuide` в `children` соответствующего раздела. Затем выполните импорт и проверку.

Папки повторяют разделы дерева: `Start`, `Ships`, `Sector`, `Activities`, `Factions`, `Combat`, `Engineering`, `Research`, `MMC`, `Medicine`, `Lore`, `Catalogue`, `References`, `Rules`. Обзор раздела обычно называется `Index.xml`. У статьи одно основное место в оглавлении; из связанных тем к ней ведут ссылки. Папка верхнего уровня должна совпадать с корневым разделом дерева.

ID страницы — постоянный адрес для статей, предметов и ролей. При перемещении XML достаточно изменить `text` в `guideEntry` и путь блока рукописи. Если статьи объединяются, прежний ID можно оставить как совместимое имя той же страницы без отдельной строки в оглавлении.

## Стиль и точность

Выбирайте материал по задачам игрока и сложности механики. Сам факт появления функции в обновлении не требует новой статьи. Исправления ошибок и косметика обычно не нуждаются в описании; инструкция нужна там, где игроку требуется понять действие, условие, ограничение или расчёт.

Начинайте руководство с результата и необходимого оборудования. Далее дайте рабочую последовательность, причины отказа и дополнительные подробности. Для сложного шага читатель должен понять: **элемент интерфейса → его смысл → действие и значение → ожидаемый результат**. Это связь между сведениями, а не обязательный набор подписей.

Например: «В поле нагрузки выставьте … . Показатель … должен … . Если он …, уменьшите …». Указывайте конкретный инструмент, кнопку, температуру, количество или допустимый диапазон. Объясняйте причины, от которых зависит выбор действия. Один шаг должен позволять выполнить определённую операцию.

- Проверяйте механику в текущем коде, прототипах и настройках сервера. Внешний гайд помогает с подачей, но может описывать другую реализацию.
- Названия предметов берите из русской локализации; названия кораблей сохраняйте как в игре. Должности и штат сверяйте с действующими ролями и `availableJobs`.
- Подзаголовки должны помогать найти задачу или число при выборочном чтении. Большие перечни характеристик, цен и рецептов находятся в каталогах; в статье остаются значения для выполнения задачи и ссылка на справочник.
- Сходные статьи оформляйте одинаково. Для фракции: база и назначение, должности, снабжение, ссылки на практические руководства. Для установки: состав, подключение, запуск, показатели и устранение отказа.
- Лор пишите связной справочной статьёй. Указывайте источники адаптации; неизвестные подробности помечайте `work in progress`.

Числа должны иметь понятные единицы и условия. Для реакции нужны пропорции и температура; для генератора — топливо и условия выдачи мощности; для защиты — тип урона и отличие от базового значения. Вес строки в таблице генерации не равен доле всех тайлов карты, а цена покупки не является оценкой продажи.

## Ссылки, оформление и изображения

Внутренняя ссылка: `[Подпись](guide://ColossusMyGuide)`. Название назначения должно соответствовать содержимому страницы. При переносе или объединении статьи проверяйте входящие ссылки и контекстные привязки.

Для кнопок и важных значений используйте `**жирный**`; цвет нужен для смысловых различий. Между заголовком, абзацем и виджетом оставляйте пустую строку. Поддерживается обычный список с дефисами; нумерованные шаги импортёр преобразует в совместимую разметку. Для формул газов используйте `O2`, `N2`, `CO2`.

Предметные иллюстрации размещаются в переносимой галерее:

```xml
<GuideEntityCards>
  <GuideEntityEmbed Entity="Wrench"/>
  <GuideEntityEmbed Entity="Screwdriver"/>
</GuideEntityCards>
```

Названия сохраняются полностью; галерея переносит предметы по ширине окна. Для сравнения используйте таблицу. Иллюстрация должна объяснять текст. Проверьте страницу в узком и широком окне: подписи, переносы, выравнивание колонок и читаемость ссылок.

## Справка по кнопке «?»

Сначала ищите подходящую статью в `_LuaM/Guidebook`. Можно оставить существующую русскую ванильную справку, если она соответствует серверу. Заменяйте её, когда текст устарел, остался на английском или наша статья лучше объясняет выбранное оборудование.

`GuideHelp` у предмета ссылается на ID страниц:

```yaml
  - type: GuideHelp
    guides:
    - IndustryMachineParts
```

Компонент наследуется: привязка на родителе действует на варианты, пока потомок не задаст собственный список. Проверяйте охват изменения базового прототипа. Для отдельной контекстной статьи используйте `Contextual/`, собственный `guideEntry` и блок рукописи; включать её в основное оглавление необязательно.

У ролей список задаётся полем `guides` прототипа `job`. Первая запись выбирается при открытии; дочерние статьи добавляются в дерево. Роли фракции открывают её обзор, наёмник и киборг наёмников — `BeginnerGuide`. У ММС список содержит обзор `ColossusMMCFaction` и производственную ветку `MMC`.

Проверяйте переходы и из полного гайдбука, и из ограниченного окна справки предмета/роли: внутренние ссылки доступны за пределами исходного набора страниц.

## Каталоги

| Данные | Разметка |
|---|---|
| Броня | `<GuideAcquisitions Kind="armor"/>` |
| Личные боеприпасы | `<GuideAutoCatalogue Kind="ammo"/>` |
| Верфи | `<GuideCatalog Kind="ships"/>` |
| Корабельное оружие | `<GuideCatalog Kind="ballistic"/>`, `energy`, `missile` |
| Серверы управления орудиями | `<GuideCatalog Kind="server"/>` |
| Генераторы | `<GuideAutoCatalogue Kind="generators"/>` |
| Аплинки | `<GuideAcquisitions Kind="uplink"/>` |
| Исследования | `<GuideNavigationUI Mode="research"/>` |
| Объекты сектора | `<GuideSites/>` |
| Дроны и регистраторы | `<GuideAutoCatalogue Kind="drones"/>`, `loot` |
| Породы и руда | `<GuideOreMatrix/>` |
| Расы | `<GuideSpeciesStats/>` |
| Цены продажи | `<GuideCommodityPrices/>` |

Существующий виджет следует переиспользовать. Общие справочники находятся в разделе «Каталог», а практические статьи ссылаются на них. Личное оружие пока имеет статус WIP; штатная статья объясняет обращение с оружием.

Сервер строит общий снимок из доступных карт, снабжения, стартовых комплектов, поддерживаемых исследований и подключённых таблиц спавна. Обработка распределена по тикам; карты ради метаданных не создаются. Снимок сбрасывается при смене раунда, конфигурации и перезагрузке прототипов. Клиент получает данные по запросу и показывает ограниченное число строк с одной областью подробностей.

При расширении каталога проверяйте **источник доступности**, а не наличие компонента у всех прототипов. Общая экипировка учитывается в группе наёмников, фракционная — по назначению и снабжению. Поддерживаемые группы: Авангард, ТСФ, СССП и ЧВК Вайпер, Колосс Централ, ММС, МЦ, Наёмники. Сохраняйте различия реальных вариантов при объединении клонов.

В «Получении» показываются станок, аплинк или автомат. Броня повторяет порядок игрового осмотра: скорость, типы урона, выносливость, взрывы. В фразе «урон снижается на 50%» число положительное; компактное изменение записывается `−50%`. Для корабельного оружия сначала нужны дальность/скорость снаряда, темп стрельбы и пополнение боезапаса.

Калибры фильтра, состав пород, дроны и их регистраторы обновляются из игровых данных. Для руд перевод `guide-ore-<ID>` уточняет подпись, но не задаёт состав. Генераторы с одинаковым названием объединены; различия характеристик остаются в подробностях. Таблица продаж содержит вещества с положительной оценкой.

После изменения отбора сравните старый и новый состав по ID и названиям. Проверьте добавленные и удалённые записи, включая наследуемые и вложенные источники. Такой отчёт нужен для ревью; его не требуется хранить среди игровых ресурсов.

## Учебные интерфейсы и планы карт

Справка использует штатные окна верфи, аплинка, навигации и исследований. Они не подключаются к рабочему BUI; операции покупки, возврата, вывода валюты и изменения реальных исследований отключены. При изменении UI проверяйте обе версии: учебную и рабочую. Подписки, учебные сущности и окна должны освобождаться при закрытии и смене страницы.

**Планы карт временно отключены.** `GuidebookMapRendering.Enabled` имеет значение `false`. Обычная сборка, упаковка и запуск сервера не запускают MapRenderer; кнопки планов неактивны. Для возврата функции нужны отдельно проверенные генерация, упаковка инструмента, доставка изображений и ограничения ресурсов. Кэш `Resources/GuidebookRenders` не входит в репозиторий.

## Проверка перед отправкой

После изменения текста выполните импорт и `--check`. Проверьте переходы, переносы галерей и соответствие названий страниц. После изменения привязок проверьте эффективный `GuideHelp` с учётом наследования и справку ролей лобби.

После C# соберите затронутые проекты и выполните подходящую проверку открытия, закрытия, повторного открытия и смены страницы. Для каталогов важны обновление данных и отключение клиента; для учебных окон — отсутствие игровых операций и утечек. Отдельно отмечайте, что подтверждено сборкой, автоматическим тестом и визуально в игре.

Текст и YAML обычно требуют обновления ресурсов и перезапуска; изменения C# требуют сборки. В PR добавьте проверяемые шаги и ожидаемый результат. Личные снимки, журналы, отчёты аудита и временные утилиты оставляйте вне PR.
